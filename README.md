# نموذج تقييم مقابلة شخصية وفنية — ICTD

فورم HTML عام (RTL) لتقييم المقابلات الشخصية والفنية لأي مرشح، مع حفظ تلقائي في Google Sheets عبر Apps Script، ورقم مرجعي فريد لكل نموذج، وإمكانية استعادة أي سجل محفوظ لمراجعته وتعديله.

### 🔒 جديد في v1.6 (مع إصلاح نهائي لمشكلة الاتصال في v1.8 عبر google.script.run) — الدخول مقيّد على حسابات الجامعة فقط
تم تطبيق **SRU Secure Access Kit**: لا يُفتح النموذج إلا بحساب Google جامعي (`@sr.edu.sa`) مُسجَّل في قائمة المصرَّح لهم، مع تسجيل تلقائي لكل محاولة دخول. **تغيّرت طريقة الاستضافة بالكامل** — انظر "خطوات الإعداد" أدناه قبل النشر.

## الملفات
| الملف | الوصف |
|---|---|
| `apps-script/Code.gs` | الخلفية الكاملة: حفظ/تحديث السجلات في Google Sheet، قوائم `?action=list/get`، **والتحقق من صلاحية الدخول (domain + قائمة AllowedUsers) وسجل AccessLog** |
| `apps-script/Index.html` | الفورم نفسه — يُلصَق في Apps Script ويُعرض تلقائيًا بعد تسجيل الدخول الناجح |
| `apps-script/Denied.html` | صفحة "غير مصرح" تظهر لأي حساب خارج الجامعة أو غير مُدرج في القائمة |
| `apps-script/Logos.html` | شعارات SRU/ICTD/ITOC المضمَّنة (Base64) |
| `github-landing/` | صفحة دخول مُصغّرة على GitHub Pages تُحوِّل المستخدم إلى رابط Apps Script (لا تحتوي أي بيانات) |
| `CHANGELOG.md` | سجل إصدارات هذا الملف |

## خطوات الإعداد (v1.6-v1.8 — بنية جديدة بالكامل)

> ✅ الشيت جاهز بالفعل في Google Drive:
> **"سجل تقييم المقابلات - ICTD"**
> https://docs.google.com/spreadsheets/d/1T54mh8JjtVzvYK5m7LUgy1ZClFrRZ7vQBBKiy2JZQG4/edit

**لماذا تغيّرت الاستضافة:** الحماية الحقيقية تأتي من Apps Script نفسه (نشره بصلاحية "Anyone within Sulaiman Al Rajhi University")، وهذا يتطلب أن يكون **الفورم نفسه** مُستضافًا داخل Apps Script (`doGet` يعرض `Index.html`) بدل أن يكون صفحة مستقلة على GitHub Pages تستدعي الشيت بـ fetch — لأن طلبات fetch من أصل خارجي (GitHub Pages) لا تحمل جلسة تسجيل الدخول بجوجل.

1. افتح الشيت أعلاه → **الإضافات (Extensions) → Apps Script**.
2. احذف كل الملفات الحالية، ثم أنشئ/الصق: `Code.gs`، `Index.html`، `Denied.html`، `Logos.html` (من مجلد `apps-script/` المرفق هنا) — احفظ (Ctrl+S).
3. من محرر Apps Script، شغّل الدالة **`setupAccessList`** مرة واحدة (القائمة ▶ أو زر Run) — ستُنشئ تبويب **`AllowedUsers`** في الشيت وتضيف المالك (`m.elmahdy@sr.edu.sa`) وقائمة افتراضية. **عدّل/أضف البريد الجامعي لكل من يحتاج صلاحية فتح هذا النموذج تحديدًا** (مثل أعضاء لجان المقابلات) في تبويب `AllowedUsers` مباشرة.
4. **Deploy → Manage deployments** → اختر النشر الحالي (الذي رابطه ينتهي بـ `/exec`) → **Edit (✏️)**:
   - **Execute as:** Me
   - **Who has access:** Anyone within Sulaiman Al Rajhi University
   - في "Version" اختر **New version** → **Deploy**.
   - **مهم:** لا تنشئ "New deployment" من الصفر — رابط `/exec` يبقى كما هو فقط عند استخدام **Edit** على النشر الحالي:
     ```
     https://script.google.com/macros/s/AKfycbw4tUzulqlefBbV-6ebAzPh68iARLk18yULqU5X6o5Ai6uMe4D-5KX5GuARhj34D0gdjQ/exec
     ```
5. **رفع صفحة الدخول:** أنشئ مستودع GitHub (مثلاً `ictsru/interview-eval`)، ارفع محتوى مجلد `github-landing/` كما هو، فعّل GitHub Pages. هذه الصفحة لا تحتاج أي تعديل إضافي — رابط Apps Script أعلاه مُثبَّت فيها مسبقًا.
6. **التجربة:** افتح رابط صفحة GitHub الجديدة → اضغط الدخول → سجّل بحساب جامعي مُدرَج في `AllowedUsers` (يجب أن يفتح الفورم) → جرّب حسابًا شخصيًا أو غير مُدرج (يجب أن تظهر صفحة "غير مصرح").
7. **رابط النموذج النهائي الذي يُستخدم ويُشارك من الآن فصاعدًا هو رابط صفحة GitHub** (من github-landing)، وليس رابط `/exec` مباشرة.

> ℹ️ **ملاحظة (v1.8):** بعد النشر بصلاحية "Anyone within Sulaiman Al Rajhi University"، قد يُعيد جوجل توجيهك فعليًا إلى رابط يتضمّن `/a/sr.edu.sa/` (مثل `.../a/sr.edu.sa/macros/s/.../exec`) — هذا طبيعي ومتوقَّع. ابتداءً من v1.8، الفورم لا يعتمد على عنوان الرابط إطلاقًا للاتصال بالشيت (يستخدم `google.script.run` بدل `fetch`)، فلا يتأثر بهذا الاختلاف في الرابط مهما كان شكله.

## الاستخدام لكل مقابلة جديدة
1. افتح الفورم — سيظهر **رقم مرجعي جديد تلقائيًا** أعلى الصفحة.
2. عبّئ بيانات المرشح وجدول التقييم والتوصية.
3. اضغط **"💾 حفظ في Google Sheets"** لتسجيل البيانات.
4. اضغط **"🖨️ طباعة / حفظ PDF"** لإصدار نسخة نظيفة للطباعة أو الأرشفة.
5. اضغط **"🆕 مقابلة جديدة"** لتفريغ النموذج والبدء بمقابلة أخرى دون إعادة تحميل الصفحة.

## مراجعة وتعديل سجل محفوظ سابقًا (أُضيف في v1.2)
1. عند فتح الفورم، تُحمَّل قائمة السجلات تلقائيًا في أعلى الصفحة ضمن **"📂 تحميل مقابلة محفوظة"**.
2. اختر السجل المطلوب من القائمة المنسدلة (يظهر التاريخ، اسم المرشح، والوظيفة، مع الرقم المرجعي).
3. اضغط **"تحميل للمراجعة والتعديل"** — ستُملأ كل حقول الفورم (بيانات المرشح، جدول التقييم الكامل، التقييم العام، التوصية، والتوقيعات) بنفس بيانات السجل المحفوظ.
4. عدّل ما تحتاجه، ثم اضغط **"💾 حفظ في Google Sheets"** مجددًا — بما أن الرقم المرجعي هو نفسه، سيتم **تحديث نفس السجل** في الشيت بدلاً من إنشاء سجل مكرر.
5. إذا أردت بدء **سجل جديد تمامًا** بعد المراجعة، اضغط **"🆕 مقابلة جديدة"** لتفريغ الفورم وتوليد رقم مرجعي جديد.
6. زر **"↻ تحديث القائمة"** يُعيد جلب أحدث قائمة سجلات من Google Sheets (مفيد إذا حُفظ سجل جديد من جهاز آخر بعد فتح الصفحة).

## إصلاح قصّ النص عند الطباعة (v1.3) وإصلاح تكرار النص (v1.4)
عند الضغط على **"🖨️ طباعة / حفظ PDF"**، يقوم الفورم تلقائيًا باستبدال جميع الحقول (نصوص، قوائم منسدلة كالتقييم) بنص كامل غير مقصوص قبل فتح نافذة الطباعة مباشرة، ثم يعيدها إلى حقول قابلة للتعديل بعد إغلاق نافذة الطباعة. لا حاجة لأي إجراء إضافي — فقط اضغط زر الطباعة كالمعتاد.

كانت نسخة v1.3 تُظهر كل نص **مكررًا مرتين** في النتيجة المطبوعة/PDF بسبب استدعاء دالة بناء النص الكامل مرتين (مرة يدويًا عند الضغط على الزر، ومرة تلقائيًا من حدث المتصفح `beforeprint`). تم إصلاح ذلك في v1.4 بجعل الدالة تُفرغ أي نسخة سابقة تلقائيًا قبل البناء، فلا يظهر أي تكرار مهما استُدعيت.

## ألوان قوائم التقييم (جديد في v1.5)
قائمة **"التقييم"** في كل صف بجدول التقييم الفني، وقائمة **"المستوى الفني العام"**، تُلوَّن الآن تلقائيًا على شكل حبة (Pill) بلون يعكس القيمة المختارة:

| القيمة | الشكل |
|---|---|
| ممتاز | أخضر داكن، نص أبيض |
| جيد جدا / جيد | أخضر فاتح، نص أخضر |
| مقبول | أزرق، نص أبيض |
| مناسب | أزرق فاتح، نص أزرق |
| ضعيف / فجوة | وردي فاتح، نص أحمر |
| غير مقيّم | رمادي فاتح، نص رمادي |

اللون يتحدّث فورًا عند تغيير القيمة، ويُطبَّق تلقائيًا أيضًا عند تحميل سجل محفوظ أو بدء مقابلة جديدة، ويبقى ظاهرًا بنفس الشكل عند الطباعة/حفظ PDF. **ملاحظة:** لإظهار الألوان في نافذة الطباعة، تأكد من تفعيل خيار **"الرسومات الخلفية" (Background graphics / More settings)** في نافذة طباعة المتصفح — بعض المتصفحات تُخفي الألوان الخلفية افتراضيًا لتوفير الحبر ما لم يُفعَّل هذا الخيار.

## تسجيل الدخول والوصول (جديد في v1.6)
- **قائمة المصرَّح لهم:** تبويب `AllowedUsers` في الشيت — عمود `active` يتحكم بالوصول دون حذف الصف؛ المالك (`OWNER_EMAILS`) لا يُستبعد أبدًا. التغييرات تنعكس خلال دقيقتين.
- **سجل الدخول:** تبويب `AccessLog` يُنشَأ تلقائيًا ويسجّل كل دخول/رفض (البريد، التاريخ، الوقت، اليوم، النتيجة). قائمة في الشيت (باسم "Interview Evaluation Form") تعرض ملخص 30 يومًا وتحذف السجلات الأقدم من 180 يومًا.
- **صفحة الرفض:** أي حساب خارج `@sr.edu.sa` أو غير مُدرج في `AllowedUsers` يرى صفحة "غير مصرح" (`Denied.html`) مع توضيح السبب.
- لا تغيير على شكل أو حقول الفورم نفسه — فقط طريقة الدخول إليه.

## النشر على GitHub Pages
- **صفحة الدخول (`github-landing/`):** ارفعها إلى مستودع منفصل (مثل `ictsru/interview-eval`) وفعّل GitHub Pages — هذه الصفحة العامة تحوي الرابط فقط ولا بيانات حساسة.
- ملفات `apps-script/` **لا تُرفع إلى GitHub** — تُلصَق داخل محرر Apps Script المرتبط بالشيت مباشرة (كما هو الحال في أي مشروع Apps Script).
- اسم مجلد هذا الإصدار (`v1.8/`) يحمل رقم الإصدار تمهيدًا للأرشفة؛ رقم الإصدار داخل الصفحة يظهر أسفل يسار الشاشة.
